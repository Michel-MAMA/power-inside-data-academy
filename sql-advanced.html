Modules Interactifs

Module 1: SELECT Avancé & Filtrage
SELECT, WHERE, LIKE, IN, BETWEEN et conditions complexes
📚 Concepts clés:
  • WHERE: Filtrer les lignes selon une condition
  • LIKE: Recherche par motif (%, _)
  • IN: Vérifier si valeur est dans une liste
  • BETWEEN: Vérifier si valeur est dans une plage
  • AND/OR: Combiner plusieurs conditions
  • ORDER BY: Trier les résultats (ASC ou DESC)
📝 Requête SQL
📤 Résultat
Cliquez sur "Exécuter"...
💡 À Retenir:

WHERE est l'outil clé pour filtrer les données. Combinaisons: BETWEEN pour plages, IN pour listes, LIKE pour motifs. Utilisez AND/OR pour conditions complexes. ORDER BY organise les résultats (ASC par défaut).

Module 2: Jointures Avancées
INNER JOIN, LEFT JOIN, RIGHT JOIN, FULL OUTER JOIN et jointures multiples
📚 Concepts clés:
  • INNER JOIN: Seulement les lignes correspondantes (intersection)
  • LEFT JOIN: Toutes les lignes à gauche + correspondances
  • RIGHT JOIN: Toutes les lignes à droite + correspondances
  • FULL OUTER JOIN: Toutes les lignes des deux tables
  • ON clause: Condition pour matcher les tables
  • Aliasing: Raccourcir les noms (e.nom = employes.nom)
📝 Requête SQL
📤 Résultat
Cliquez sur "Exécuter"...
💡 À Retenir:

Les jointures combinent des données de plusieurs tables. INNER JOIN = strictement les deux. LEFT/RIGHT = tout d'un côté + correspondances. Utilisez des alias (e, d) pour clarifier. ON clause = condition pour matcher.

Module 3: GROUP BY & Agrégations
COUNT, SUM, AVG, MIN, MAX, GROUP BY, HAVING et statistiques
📚 Concepts clés:
  • COUNT(*): Compte les lignes
  • SUM: Somme des valeurs
  • AVG: Moyenne
  • MIN/MAX: Minimum et maximum
  • GROUP BY: Regrouper les résultats par colonne
  • HAVING: Filtrer les groupes (comme WHERE pour GROUP BY)
📝 Requête SQL
📤 Résultat
Cliquez sur "Exécuter"...
💡 À Retenir:

GROUP BY agrège les données par catégories. Combinaison classique: GROUP BY + COUNT/SUM/AVG/MIN/MAX. HAVING = WHERE pour les groupes. Toujours inclure les colonnes non-agrégées dans GROUP BY!

Module 4: Sous-requêtes & CTE (Common Table Expressions)
WITH, sous-requêtes, requêtes imbriquées et requêtes récursives
📚 Concepts clés:
  • CTE (WITH): Common Table Expressions - requête nommée réutilisable
  • Sous-requête: Requête imbriquée dans SELECT/WHERE/FROM
  • Avantage CTE: Plus lisible que sous-requêtes imbriquées
  • Récursif: Hiérarchies (organigrammes, arbres)
  • Readabilité: Diviser requête complexe en étapes logiques
📝 Requête SQL
📤 Résultat
Cliquez sur "Exécuter"...
💡 À Retenir:

CTE (WITH) rend les requêtes complexes lisibles. Divisez en étapes logiques. Sous-requête utile pour filtrer (WHERE) ou transformer (FROM). Pattern: CTE calculée une fois, réutilisée. Pour hiérarchies: utilisez WITH RECURSIVE.

Module 5: Window Functions (Fenêtres)
ROW_NUMBER, RANK, DENSE_RANK, LAG, LEAD et analyses temporelles
📚 Concepts clés:
  • Window Functions: Opérations sur partitions de données
  • PARTITION BY: Diviser fenêtre par catégories
  • ORDER BY: Trier dans la fenêtre
  • ROW_NUMBER: Numérotation séquentielle (1,2,3...)
  • RANK/DENSE_RANK: Classement avec ou sans lacunes
  • SUM/AVG OVER: Agrégations sans grouper les lignes

Window Functions = agrégations sans grouper. PARTITION BY divise en "fenêtres". ROW_NUMBER pour classement, RANK pour positions avec ex-aequo. LAG/LEAD pour comparaisons temporelles. Très puissant pour analyses comparatives!

Module 6: Union, Except, Intersect & Optimisation
Opérations d'ensemble, performances et best practices SQL
📚 Concepts clés:
  • UNION: Combine 2 requêtes, supprime les doublons
  • UNION ALL: Combine sans enlever les doublons (plus rapide)
  • INTERSECT: Lignes présentes dans les 2 requêtes
  • EXCEPT: Lignes de la 1ère qui ne sont pas dans la 2e
  • Performance: Filtrer avant UNION, indexer les colonnes clés
  • Best Practices: Colonnes mêmes types, lisibilité, commentaires
📝 Requête SQL
📤 Résultat
Cliquez sur "Exécuter"...
💡 À Retenir:

UNION combine résultats et déduplique (coûteux). UNION ALL plus rapide. INTERSECT/EXCEPT pour opérations d'ensemble. Toujours utiliser UNION ALL si dédupli pas nécessaire. Filtrer dans les sous-requêtes avant UNION pour performance. Cohérence des types!
